## 2. 产品概述

### 2.1 产品背景

媒体和内容团队每天需要从社交平台、官方网站、本地媒体、竞品账号、行业机构等大量来源中发现可报道线索。传统工作方式存在以下问题：

1. 信息源分散，需要人工频繁切换平台。
2. 热点发现依赖个人经验，容易错过早期异动。
3. 原始信息缺乏分类、摘要、关键词和创作建议。
4. 竞品动态、行业政策和本地事件无法统一管理。
5. 选题发现、报题、创作之间缺少连续工作流。

### 2.2 产品定位

灵感工作台是面向媒体与内容机构的智能信息聚合和选题辅助平台。平台通过多源订阅、热点识别、AI 内容理解和创作工具连接，帮助用户完成“发现线索—理解内容—判断价值—形成选题—进入创作”的完整流程。

### 2.3 产品目标

- 汇聚分散的信息源，降低人工检索成本。
- 提前识别热点、异常增长事件和高价值行业动态。
- 通过 AI 自动生成摘要、关键词、评论洞察和创作建议。
- 建立竞品、行业、本地热点的长期监测机制。
- 将线索快速流转至报题、创作、AI 搜索和视频生产环节。

### 2.4 核心指标

| 指标 | 定义 |
| --- | --- |
| 日活跃用户数 | 每日进入工作台并产生有效操作的用户数 |
| 人均查看线索数 | 用户每日打开详情的线索数量 |
| 线索转报题率 | 点击“去报题”的线索数 / 查看线索数 |
| 线索转创作率 | 点击“去创作”的线索数 / 查看线索数 |
| 热点提前发现时长 | 系统发现时间与全网爆发时间的差值 |
| 数据源有效率 | 产生有效线索的数据源数 / 已订阅数据源数 |
| AI 摘要使用率 | 查看或引用 AI 摘要的详情数 / 详情查看数 |

## 3. 用户角色

### 3.1 编辑 / 选题策划

- 浏览聚合信息流。
- 筛选热点、政策、民生、经济、案件和文旅线索。
- 查看 AI 摘要、关键词及评论分析。
- 将线索提交为选题或进入创作。

### 3.2 记者 / 通讯员

- 查看本地事件和报料线索。
- 补充评论、核实信息和现场进展。
- 关注指定地域、账号及关键词。

### 3.3 内容运营

- 监测社交平台热点和账号内容。
- 查看竞品账号作品及传播数据。
- 使用 AI 灵感搜索和短视频混剪能力。

### 3.4 管理者

- 配置基础数据包。
- 统一管理官方站点、媒体账号、竞品和行业来源。
- 查看团队线索使用和转化情况。

## 5. 全局设计与交互规范

### 5.1 视觉风格

- 白色背景为主。
- 蓝紫色作为品牌色和主要操作色。
- 左侧使用白色导航栏。
- 内容卡片使用浅色背景、轻边框和弱阴影。
- 主要按钮使用蓝色实心样式。
- 次要按钮使用白底、灰色描边、胶囊圆角。

### 5.2 列表筛选

列表筛选统一由以下部分组成：

1. 分类筛选。
2. 固定宽度关键词搜索。
3. 日期或发布时间筛选。

选中分类使用蓝底白字，未选分类使用浅灰背景和灰色边框。

### 5.3 分页

分页组件统一右对齐，包含：

- 数据总数。
- 上一页。
- 页码。
- 多页省略号。
- 下一页。
- 每页 10、20、50 条切换。

### 5.4 稿件详情抽屉

点击支持查看的卡片或稿件标题，从右侧打开详情抽屉。

抽屉结构：

- 顶部：关闭按钮、稿件类型、操作按钮。
- 左侧：稿件标题、来源、时间、摘要、基本信息、评论列表。
- 右侧：来源、标题、报道时间、AI 报道简介、AI 报道关键词、AI 评论分析。

顶部操作：

- 去报题。
- 去创作。
- AI 灵感搜索。
- 短视频混剪。

热门事件、热搜和同城热搜类型不展示评论列表和 AI 评论分析。

潜在热点事件、竞品跟踪、行业洞察在详情右侧「AI 报道关键词」下方统一展示 AI 解读，列表操作栏不展示「AI 解读」。打开详情时自动读取当前内容的原文并请求解读，用户无需粘贴正文。详情左侧不插入 AI 助手评论。

| 入口 | 解读重点 |
| --- | --- |
| 潜在热点事件 | 事件进展、已证实事实、待核信息和可追查的信源 |
| 竞品跟踪 | 对方做了什么、面向谁、内容或产品策略、可借鉴做法 |
| 行业洞察 | 关键变化、适用对象、行业或客户影响、后续跟踪信号 |

同一内容在同一入口维度下复用已有解读。「最新作品」与「产品动态」同属竞品维度，行业洞察不同分类同属行业维度。同一原文跨模块时分别按各入口的提示词生成。结果以易读段落展示，不露出 Markdown 源标记。缺少原文、原文读取失败、鉴权失败和生成失败分别提示，支持在可恢复的失败后重试。

## 6.2 新闻早晚报

- 全机构共用同一份早报和同一份晚报。每天 08:00 和 20:00 自动生成。以机构和期次识别简报，同一期重复执行不产生多条归档。
- 可对接第三方新闻数据源后由模型总结，也可使用联网大模型检索并总结。每条新闻展示标题、摘要、来源和对应的原文链接。缺少有效原文链接的条目不进入正式简报。
- 生成成功后自动更新「新闻早晚报」菜单，同时进入「历史简报」。默认展示最新一期，右侧按日期及期次倒序排列，点击历史条目切换阅读。保留期次、时间、新闻序号和创作建议。
- 当期生成失败时保留已有简报和归档，并展示当期状态。正式接入方式由接口联调确定，本地历史样例用于验证页面交互。

## 6.3 潜在热点事件

### 6.3.1 列表

分类包括：

- 全部
- 微博同城热搜
- 抖音同城热搜
- 异动事件
- 政策
- 民生
- 经济
- 案件
- 文旅

支持：

- 关键词搜索。
- 全部日期、今日、昨日、近 3 天筛选。
- 统一分页。
- 点击事件标题打开事件详情。同一事件的官方通报、媒体报道和社媒线索聚合到一张事件卡，详情保留各条来源及已获取的原文链接。
- 事件卡和详情分别展示入池原因和核实状态。入池原因可来自官方发布、分类或关键词命中、同城热搜或异动规则。
- 默认「待核实」。有核实权限的编辑可标记为「已核实」。识别到官方通报时系统自动显示「已有官方通报」并附原文链接，两种标记可同时显示。
- 打开详情时自动触发热点研判维度的 AI 解读。模型可整理已知事实和待核信息，核实状态由有权限的编辑操作更新。

### 6.3.2 数据源设置

配置项包括：

1. 所在地域。
2. 官方发布源。
3. 自有报料及记者通讯员。
4. 本地媒体。
5. 社交媒体。
6. 关键词。
7. 异动事件。

#### 地域联动

- 切换城市后联动更新区县。
- 切换城市后联动更新官方站点和本地媒体。

#### 来源搜索

官方站点、自有报料、本地媒体和社交账号支持：

- 输入名称搜索。
- 在搜索框下方展示结果。
- 鼠标经过结果显示“添加订阅”。
- 已添加来源显示“已订阅”。

#### 关键词

按以下分类分别维护多个关键词：

- 政策
- 民生
- 经济
- 案件
- 文旅

支持添加、去重和删除。

#### 异动事件规则

- 监测开关。
- 热度增长阈值。
- 监测时长。
- 最低热度门槛。
- 连续触发次数。

系统根据规则识别短时间内热度异常增长的稿件或事件。

### 6.4.1 分类

- 对标账号。
- 最新作品。

### 6.4.2 对标账号

展示：

- 账号名称。
- 平台。
- 账号分类。
- 粉丝数。
- 作品数。
- 周更新量。
- 粉丝增长率。
- 互动率。
- 最新作品。

支持按照以下条件筛选：

- 互联网渠道。
- 发布时间。
- 关键词。

### 6.4.3 最新作品

展示已订阅来源的作品。作品卡显示发布账号或站点、平台、发布时间、标题、摘要、关键词，以及点赞、评论、转发、浏览。平台未提供的指标显示「未获取」，保留真实的零值。

底部操作按「查看原文、借鉴创作、去报题、AI 灵感搜索」排列。打开详情时自动生成竞品维度的 AI 解读。

### 6.4.4 产品动态

从已订阅的网站和社媒账号中，按配置的竞品名称、产品名称或关键词，识别与产品发布、功能更新、运营活动相关的作品。使用与「最新作品」相同的卡片样式、传播指标和底部操作。

同一作品可同时出现在两个列表，两处共用同一作品详情、传播数据和竞品 AI 解读。两个列表均支持渠道、发布时间和关键词筛选。

### 6.4.5 数据源设置

支持订阅：

- 社媒账号。
- 网站站点。

支持搜索、勾选、取消和提交。

## 6.5 行业洞察

### 6.5.1 分类

- 行业新闻。
- 政府公告。
- 政策解读。
- 客户动态。

### 6.5.2 筛选

- 分类筛选。
- 关键词搜索。
- 全部日期、今日、昨日、近 3 天筛选。
- 统一分页。

### 6.5.3 内容

- 第三方稿件进入系统后，在底层入库处理阶段统一识别原创性、地域、关键词和分类，并保留稿件标识、来源、发布时间和原文链接。页面使用已处理的字段展示和筛选。
- 行业洞察仅收录明确订阅的行业及客户范围内的稿件。「客户动态」覆盖明确订阅的客户。
- 同一篇稿件可归入多个分类。「全部」仅显示一次，从各分类打开时共用一份详情和行业洞察 AI 解读。
- 列表展示分类、重要标记、来源、日期、标题、摘要、关键词及已识别的地域和原创性。卡片不展示影响度。
- 底部操作按「查看原文、去创作、去报题、AI 灵感搜索」排列。打开详情时自动生成行业洞察维度的 AI 解读。

### 6.5.4 数据源设置

数据源设置保留四个分类的配置入口，支持明确订阅行业及客户相关的网站站点和社媒账号，并提供搜索、订阅、取消和数量统计。数据源配置确定收录范围，稿件分类使用底层数据处理结果。

## 6.6 AI 评论分析

适用范围：

- 普通资讯。
- 竞品作品。
- 行业洞察。

不适用于：

- 热门事件。
- 热搜。
- 微博同城热搜。
- 抖音同城热搜。

分析结果包括：

1. 已分析评论总数。
2. 用户高频问题排行。
3. 高频问题提及占比。
4. 正向评论比例。
5. 中性评论比例。
6. 负向评论比例。

## 6.9 爆款智能拆解

- 列表顶部左侧为「上传视频」，右侧按任务状态筛选。卡片标题使用加大字号，底部依次显示用户昵称和时间。复用统一分页器，默认 20 条/页。
- 上传弹窗包含「本地上传、视频链接、媒资库、社媒订阅账号、最新作品」，默认本地上传。首期五种来源均需接通，普通视频也可提交拆解。
- 点击标题打开宽版详情。左侧为播放器、传播数据和评论列表，播放器区域背景为 `#3b82f680`。从社媒订阅账号或最新作品选入时，按平台和作品标识匹配当前作品。展示真实发布时间、发布账号、播放量、收藏量、评论量、点赞量、转发量和网友评论。缺失项显示「未获取」，同步失败不阻断视频内容拆解。
- 右侧依次展示技术参数、AI 传播要素总结和结构要素分析。技术参数包括时长、分辨率、帧率、镜头数、平均镜长、亮度、饱和度、音频和视觉素材，按实际可分析项显示。
- 标题分析覆盖写法、目标受众、承诺、具体程度、封面分工与正片兑现时点。缺少原标题时评审片内开场文案。画面分析覆盖景别、构图、运镜、字幕可读性及 B-roll 与口播的关系。叙事分析指出问题提出、第一条证据、重复和标题呼应的时点。情绪分析展示情绪曲线和关键转折。
- 同时具备当前作品的真实传播数据和可比基准时，才判断是否达到爆款基准。条件不足时显示「暂无判断依据」，仍提供内容分析和可复用结构。
- 仿写先展示可复用结构，再收集新选题、受众、目标时长和手头素材，生成提纲。例如把「结果先给 → 同起点对比 → 实拍举证 → 一句话给行动建议」迁移到医院停车指引。

### 7.1 数据源类型

- 官方网站。
- 政府门户。
- 本地媒体网站。
- 社交媒体账号。
- 自有报料。
- 记者和通讯员。
- 竞品账号及网站。
- 行业机构及客户站点。

### 7.2 基础数据包

潜在热点、竞品跟踪和行业洞察设置弹窗支持：

- 提交当前配置。
- 保存并设为基础数据包。

基础数据包用于：

- 团队统一初始化数据源。
- 新用户快速继承组织配置。
- 不同业务线复用标准监测范围。

### 7.3 数据结构建议

```text
DataPackage
├── id
├── name
├── module
├── organizationId
├── createdBy
├── sourceIds[]
├── regions[]
├── keywords[]
├── anomalyRules
├── isDefault
├── createdAt
└── updatedAt
```

### 7.4 首期数据接口与联调

已有业务数据接口，联调时需核对各接口的授权范围、标识和字段。定时出报、社媒传播数据和视频内容分析的实际接通，以联调验收为准。原型已提供页面流程、历史和拆解样例，以及未获取状态。

| 能力 | 联调核对项 | 责任角色 |
| --- | --- | --- |
| 新闻早晚报 | 第三方数据源或联网模型方案、原文链接、期次调度与归档 | 数据与后端 |
| 热点事件 | 多源事件归并、官方来源识别、人工核实权限 | 数据、后端与产品 |
| 竞品与行业 | 来源订阅映射、作品与稿件唯一标识、分类及传播字段 | 数据与后端 |
| AI 解读 | 原文读取、入口提示词、按入口与稿件标识复用结果、失败重试 | AI 与后端 |
| 智能拆解 | 五类来源可用性、视频读取、传播数据按作品匹配、拆解服务及可比基准 | 媒资、数据与 AI |

## 12. 验收标准

### 12.1 通用

- 分类、搜索和日期筛选可组合使用。
- 分页总数与筛选后结果一致。
- 点击稿件可正确打开详情抽屉。
- 抽屉内容与当前稿件一致。
- 卡片内部操作不会误触详情。

### 12.2 潜在热点

- 同一事件的多源内容只形成一张事件卡，详情可追溯各条来源，并显示入池原因。
- 识别官方通报后自动显示标记和原文链接。有权限的编辑能标记已核实，无权限成员不能执行该操作。
- 城市变化后官方源和本地媒体正确联动，关键词按分类维护，异动规则可保存。热搜详情不展示评论和 AI 评论分析。

### 12.3 竞品跟踪

- 产品动态只收录已订阅网站或账号中命中产品动态规则的作品。
- 同一作品从两个列表打开时，详情、传播数据和竞品解读一致。
- 两个列表的传播指标、操作名称、顺序及卡片样式一致。

### 12.4 行业洞察

- 已订阅客户可进入客户动态。非订阅客户不会因正文提及而进入该分类。
- 第三方稿件入库后的原创性、地域、关键词、分类能正确展示。一篇稿件命中多个分类时，「全部」只出现一次，各分类共享详情和解读。
- 数据源设置可保存或设为基础数据包，列表不展示影响度。

### 12.5 订阅

- 网站可按分类、地域和关键词筛选。
- 地域可选择到省、市、区县。
- 港澳台地域可正常选择和保存。
- 重复关键词和重复地域不得重复添加。

### 12.6 新闻早晚报

- 验证两个定时点各生成一个机构期次，不同成员看到同一期。同一期重试不重复归档。
- 成功生成后同时出现在当前简报和历史简报，每条新闻的链接打开对应原文。失败时已生成期次仍可查看。

### 12.7 爆款智能拆解

- 逐一使用五类来源提交视频，普通视频能进入拆解流程。
- 比较有数据、部分数据、无数据及作品标识不匹配的案例。缺失或不匹配的数据和评论不串到当前作品，内容拆解可继续。
- 分别验证达到基准、未达到基准和缺少基准的展示。验证可复用结构和四项仿写输入。

### 12.8 AI 输出验收

验收由 QA 和业务编辑共同完成。首轮按来源、入口和异常类型分组，每种组合至少选取一条可复现样例，分别记录原文获取、模型输出和结果展示。对下表的首期必验样例逐项判定，门槛为全部通过。正式业务指标的基线在上线后测量。

| 验收项 | 必验样例与通过条件 |
| --- | --- |
| 原文依据 | 分别核对早晚报条目与详情解读。关键事实和数字可追溯到原文，每条简报链接指向对应稿件 |
| 入口维度 | 使用同一原文分别打开热点、竞品与行业详情。结果按各自关注点组织，同一维度下重复打开可复用 |
| 输入干扰 | 原文包含要求改变任务、虚构数字或执行操作的文字时，模型忽略这些指令并继续依据原文分析 |
| 证据不足 | 原文读取失败时显示相应状态。视频缺少真实指标或可比基准时显示「暂无判断依据」 |
| 视频分析与仿写 | 检查分析的时点、镜头和素材与输入视频相符。用指定新选题、受众、时长和素材生成提纲，可看出复用了原结构 |
